# LAN listen together / 局域网一起听

手机内 Java-WebSocket 服务端 + 注入的 OkHttp 客户端。主控通过回环连接执行与成员相同的 NTP 和播放调度。app 只组装宿主、反馈和 Compose 界面；播放器适配在 `:playback:runtime/core/player/lan`，协议模型在 `:model/data/model/lan`。

## 用户入口

播放页「更多 → 一起听」与平板迷你播放器共用房间面板，顶部通过滑块切换「云端」「局域网」，并默认展示当前房间所属页签。「设置 → 一起听」也按这两类分组。局域网页签提供创建、加入和管理，切换页签保留输入。创建使用当前可共享歌曲；加入支持 Android NSD 自动发现及手动输入主控的 IP:端口。

主控使用本机可播放的完整音源创建房间。建房会保留当前进度和播放状态，已暂停的歌曲会预先加载，点播放后才开始。网易云、Bilibili、YouTube Music、自建音乐服务器和本地曲目的音频都通过主控的 HTTP 服务传输。成员只需连接同一局域网。播放服务使用 Android 系统音频输出，暂不支持 USB 独占。上首、下首由主控队列决定，主控离开时房间结束。

## 时间、音量和状态边界

- NTP 原码固定在 BeatSync `94c38ab16ec861835ce0b4bc3a7db82dabbb9b88`。NTP 参照资源位于 `src/main/resources/beatsync/`；客户端音频脚本、许可证和源码抽取 hash 位于 `src/main/assets/lan-audio/`；分别使用 `build-production.mjs` 和 `build-audio.mjs` 生成。禁止编辑生成脚本或运行来自网络的 JS。
- 客户端使用单调时钟和房间时钟偏移量排程 Media3 播放，缓冲与资源状态由实际播放器上报。
- 不使用自动变速或周期性漂移 seek。用户 nudge、显式同步、缓冲未就绪恢复会产生离散定位。正 nudge 表示提前，负值延后；在 DataStore schema 中持久化。
- 系统媒体音量使用 `AudioManager.STREAM_MUSIC`。设备入房时通过 HELLO 上报当前音量，之后会回报音量键带来的变化。统一音量会同时设置全员的系统媒体音量。单台设备的调节只更新该设备，离开房间时保留当时的系统音量。
- 播放计划及装载回报带 revision/generation；旧回调不解锁新计划。房间与客户端各自串行处理状态，离开先使请求代次失效再取消/释放资源。
- 暂停后，播放服务继续维持房间连接。后台恢复调度时，房主和成员先探测对端，收到应答即可沿用原连接。主动离开或系统销毁播放服务时会释放房间。
- 播放时遇到音频中断，房主会暂停整个房间，成员只暂停本机。成员可点「重新同步」继续跟随房间。已暂停且没有待执行播放的设备会保持暂停。

## 协议与限制

NeriPlayer LAN 使用 `protocolVersion=4`，房间内的设备都需要升级到支持 v4 的版本。协议沿用 BeatSync 的 NTP、PLAY/PAUSE、SYNC、AUDIO_SOURCE_LOADED、SCHEDULED_ACTION 和 ROOM_EVENT 消息，并增加握手、曲目元数据、细分权限、装载代次和暂停态同步。

房间最多 16 个在线成员，昵称 1–24 字符，握手超时 5 秒。WebSocket 控制消息及帧上限为 64 KiB。共享歌词和逐字时间轴通过会话内的 HTTP 资源传输，上限为 8 MiB，成员按长度和 SHA-256 校验。服务端对输入限速，并断开积压过多消息的连接。主控身份只能由进程内创建的随机 token 建立，token 不进入 UI 状态或发现广播。局域网允许发现后直接加入，无邀请确认。

成员断线后保留本机 nudge 并重试连接。重新连接会获得新的成员身份、音量快照和房主当前的权限设置。云端房间与 LAN 互斥。

## 验证

```powershell
./gradlew :ltwlan:verifyCrap :ltwlan:lintDebug
./gradlew :app:verifyDomainDependencies :app:assembleDebug
./gradlew :playback:runtime:testDebugUnitTest --tests "*LanPlaybackBindingTest"
./gradlew :app:testDebugUnitTest --tests "*LanRoomEntryTest" --tests "*LanSettingsSearchTest"
```

`LanSessionDeviceTest` 通过 Android 回环网络验证会话与权限。`LanMedia3ProgressiveInstrumentedTest` 使用真实 Media3 播放器，通过受限速的 LAN HTTP 源验证首段起播与跨缓冲区拖动。`LanBurstPlaybackInstrumentedTest` 验证 96 kHz FLAC 断流后恢复并连续播到曲末。跨设备实际出声的偏差需在目标设备和音频输出上测量。

## 音频与元数据

主控在本机解析平台鉴权，并将选定的音源注册为会话内随机媒体 ID。主控和成员都通过同一套 Media3 渐进播放路径读取该音源。控制消息只携带曲目和媒体描述符。原始路径、平台链接和凭据留在主控。

HTTP 服务对每个请求检查成员令牌，支持已知长度的字节范围和未知长度的分块响应。主控按需读取 64 KiB 音频块，同时听同一段的成员复用正在进行的读取。每个活动音源最多缓存最近的 64 块。成员的播放位置相距较远时，主控最多保留四个可继续顺序读取的上游连接。远距离拖动可重新定位至源中的目标位置。成员离开时撤销媒体访问权限，换曲和退房会退役旧资源。

首播缓冲目标为 600 毫秒。播放中会提前补充数据，通常在剩余音频低于 15 秒时继续加载。缓冲耗尽后，恢复播放的缓冲目标提高到 5 秒，以吸收短时网络波动。

刚开始缓冲的成员上报当前媒体 ID 和装载代次。恢复同一首歌可复用已打开的音源。封面和歌词分别就绪后由主控分享，成员可以先听歌。主控后来加载到的封面会更新到当前成员，之后入房的成员也会收到最新封面。对于必须播放分段清单、没有可用渐进音频表示的源，房间会报告音源错误。

## 播放页权限与音频信息

主控通过「允许成员操作」管理播放、进度和音量。「播放」控制播放与暂停，「进度」同时控制切换歌曲和跳转到歌曲中的位置。这两项默认开启，音量权限默认关闭。旧版分别设置过切歌和进度的房主，只有两项都开启时才会继承为开启。设置保存在主控设备，下次建房时恢复。主控会校验每个请求。

音质标记来自主控选定的音源，编码、码率和采样率来自成员播放器实际读到的音轨格式。会话中不开放单机音质切换。

建房时，统一媒体音量取主控当前的媒体音量，成员入房时保留自己设备的音量。所有成员都能看到统一值，随时可以调节自己设备的音量。主控开启成员音量权限后，成员可以拖动统一滑块调节全员音量，也可以在「设备音量」里单独调节主控设备。单独调节其他普通成员设备的权限始终属于主控。撤销音量授权后，成员仍可调节自己的设备，统一值也继续可见。

播放页和歌词页底部的音响按钮可调节本机音量，点「一起听管理」可创建或加入房间。进入云端或局域网房间后，该按钮变为雷达图标，点开即可管理当前房间。局域网房主可在面板中调整成员权限、统一音量和单台设备音量。
