# LAN 本地音乐同步接入准备

日期：2026-10-29。状态：已完成本地代码梳理与设计准备，尚未实现本地文件传输。现有在线音源行为继续保留。本期目标是主控播放本地文件，成员无需事先拥有文件，仍沿用原生播放页和 BeatSync 调度。

## 已确认的限制

- `LanPlaybackBinding.track()` 使用 `includeLocal = false`，本地歌曲不能进入房间。
- `LanRoomPolicy.validIdentity()` 仅接受 netease/bilibili/youtubeMusic。
- `LanPlayerAdapter.resolveSharedAudioSources()` 与 `sharedAudioSources()` 复用在线平台解析和白名单，没有本地文件分支。
- `LanAudioFileLoader.download()` 仅接受 HTTP(S)，负责受限下载、时长和内存检查。
- `LanAudioMetadata.lanAudioSource()` 没有 LOCAL 分支。
- `ListenTogetherTrack` 虽有 mediaUri，但主控的 content URI/绝对路径不能供另一部手机读取。现有云端 local 映射不能直接承担跨设备传输。
- 当前控制 WS 有 64 KiB 帧上限、消息限速与慢发送断连策略；音频传输需要独立连接，避免大文件占用 NTP/控制消息发送队列。

## 首版范围与决策

1. 支持应用已可读取的本地单文件音频，包括文件路径、MediaStore 和已获授权的 SAF URI。托管下载文件只要存在可读本地实体，也按文件来源处理，不因歌曲仍带在线 channelId 而再次请求平台。
2. 主控提供当前曲目的完整文件字节。全体成员完整接收、验证并解码后，由现有屏障统一起播。主控也播放同一份不可变快照。
3. 不要求同名文件匹配，不扫描副设备媒体库，不将会话文件自动导入歌单或下载目录。
4. 首版不做实时转码、边下边播、跨网穿透、主控移交。沿用当前 40 MiB 编码文件、192 MiB 预计解码 PCM、双声道预算；容器与编码能否使用必须以现有原生检查和 Web Audio 实际解码成功为准。不能承诺所有 FLAC/长音频均可用。
5. 播放控制、权限记忆、系统媒体音量、原版音质展示及零默认偏移全部复用。文件来源显示“本地”，编码/码率/采样率来自文件，不能把无损标签或在线音质等级凭空补出来。

## 推荐数据路径

主控本地 URI → 应用私有会话快照 → SHA-256/时长/格式 → 独立媒体下载通道 → 成员临时文件 → 完整校验 → 现有 Web Audio load → 全员 ready → 现有绝对时刻 schedule。

控制面继续 Java-WebSocket + OkHttp。媒体面拟采用主控独立 HTTP 服务，由成员原生 OkHttp 下载；WebView 仍只读设备自己的受限本地资源。HTTP 服务实现/依赖在编码前做小型验证后选定，本准备阶段不引入未经验证的依赖。若只能通过大幅自写 HTTP 解析器实现，应改为评估独立的二进制 WS 文件通道，而不是把文件塞入现有控制 WS。

HTTP 首版只需当前资源的 GET/HEAD 与固定 Content-Length，断线失败可从头重取；不实现 Range 时明确返回完整 200，不能伪造 206。大文件续传留待实测需要后再增加。

## 身份与协议

新增 LAN 专用媒体描述符，示意字段：

- kind：remote 或 localFile；现有远端候选与本地描述符走不同校验路径。
- mediaId：不透明随机会话资源 ID；服务端只据登记表查找资源。
- contentSha256、byteLength、durationMs、mimeType：固定快照的身份和校验信息。
- 本地曲目的 LAN 身份使用完整文件 hash，例如 local:<sha256>；相同标题但不同内容不得当作同一音频。hash 表示字节一致，不证明采样时钟一致。
- 下载端口由已连接主控告知，成员从当前控制连接的主控地址构造 endpoint；不接受任意重定向或未登记的绝对文件 URL。
- 每个成员的短期下载凭据通过已加入的控制会话单独发放，放请求头，不进入房间公共快照、NSD、日志或普通 SongItem。

采用 LAN 协议版本 3 并同时更新服务端、客户端、NSD 和测试。旧版明确拒绝连接，云端 Worker 协议不变。不要仅放宽原平台 URL 白名单来允许任意局域网地址。

主控本地路径/SAF URI 只留在主控私有资源登记表；对外只发布展示元数据与不透明身份。封面和歌词中的本机路径同样不能广播：首版缺少可共享资源时使用默认封面，歌词复用现有可用来源；本地封面/歌词文件传输另列后续工作。

## 资源生命周期与并发

- 准备时从现有本地媒体入口解析 URI，持有已授权读取能力，边复制边 hash 并实施字节上限；不使用不受限 readBytes。
- 源长度未知时按实际读入总量限制。源被删除、权限撤销或读到一半失败，删除不完整临时文件并给出明确失败状态。
- 完整副本通过检查后原子登记，解决扫描后文件变动与不可 seek 的提供者问题；主控与成员读取同一快照，不直接暴露整个目录。
- 成员使用 .part 临时文件，长度、SHA-256、时长和预算全部通过后才发布 ready。晚加入与重新同步也必须比较主控规范 hash，不能只校验当前装载屏障内的成员。
- 切歌、取消、成员离开、服务停止时撤销相应凭据/代次并取消 I/O。取消中的旧回调不得更新新歌曲、覆盖音质或解锁新屏障。
- 控制线程不复制文件；原生 I/O 使用有界并发。首版拟限制主控同时 2 个下载，额外成员有界排队，具体并发和准备超时通过真机验证。不能沿用 90 秒超时却忽视最多 16 人的排队耗时。
- 快照在所有读取者释放后删除；仅保留当前曲目及取消过程中仍被读取的上一份快照，额外设置会话磁盘总量预算，避免快速切歌累积。
- 会话下载权限只控制当前已共享文件，不提供目录浏览、文件上传、任意路径读取。现有 LAN 是可信局域网中的明文会话，下载 token 不是对同网监听者的加密保护。

## 验收矩阵

- 主控有文件、成员无文件，能创建/加入并完整播放超过 30 秒；两端 hash、实际时长、来源/编码一致。
- 本地文件、MediaStore、SAF；未知长度、权限撤销、文件消失、空文件、损坏文件、超过预算分别有明确结果。
- 网易云 → 本地 → B 站 → 本地连续切换，不残留来源、音质、封面路径或旧装载回调。
- 暂停/恢复/seek/上一曲下一曲、授权及撤权、权限重启记忆、主控与成员系统媒体音量保持既有语义。
- 晚加入、重连、正在下载时切歌或退房、主控离开、资源正在读取时清理均不崩溃、不泄漏、不播放过期文件。
- 未加入/错误凭据/已离开成员取不到文件；任意路径、外部重定向、错长度/错 hash、磁盘不足均被拦截。
- 合成端到端文件传输用自建测试音频；真实私人音乐和凭据不提交仓库。
- 运行 CONTRIBUTING 要求的 LAN CRAP/lint、领域依赖、模块边界和播放器/设置定向回归。真实声音 10ms 指标仍需后续声学测量，不能用进度读数代替。

## 实施修订（2026-10-30）

用户将编码音频上限调整为 100 MiB，PCM 预算仍为 192 MiB；取消旧客户端兼容提示专项。封面、歌手、歌词必须复用软件现有来源解析及展示优先级，原先不传本地封面/歌词的限制取消。传输主控解析后的歌词行、逐字时序、翻译、音译和偏移，并将本地封面登记为会话资源；不能仅给成员传主控文件路径。

已新增（尚未接入运行会话）：100 MiB 有界快照、独立 NanoHTTPD 服务、成员 token 授权/撤销、两路传输限制及四路连接执行器、原生 OkHttp 下载和完整长度/hash 校验。HTTP 服务及下载测试共 6 项通过，LAN lint 通过。快照取消返回时清理又作了补强，需再运行定向测试。

仍需完成：主控本地曲目到 hash 身份的映射；会话资源端口与私发成员下载凭据；本地 LOAD/晚加入/重连；播放器接入；封面/歌词加载与发布；进度/错误文案；资源总量和切歌清理集成；完整双机验收。尚未宣称本地音乐可用。

### 真机首轮证据（2026-10-30）

两台 Debug 已安装本地共享初版。主控独有合成 MP3（65秒）、蓝色封面与4行LRC，成员无原文件。成员晚加入后成功下载，双方实际解码时长65秒，播放观察超过46秒；副设备播放页显示本地文件、正确歌名/歌手、MP3、44.1kHz / 192kbps及同步歌词行。两端音频 SHA-256 为 `7a6e06d7d6cfc81d322c0233a45a82917c3c60edbbca7670fdda52be82fb2b71`；封面和presentation文件hash也一致。暂停后成员显示停止状态。

用户随后在当前房间切换真实本地歌曲，双方均显示相同名称、歌手、封面、320kbps MP3及约305秒解码时长；当时该曲共享歌词为空，尚不能据此认定所有歌词来源完整验收。保留房间供用户试听，未清除账号或私人文件。

仍需验收并修复：最终质量门禁、传输进度、实际seek/恢复与退出清理、SAF/嵌入歌词/云端补全与用户修改结果、多轮在线本地切换。100MiB精确边界测试已加入。不能将本记录当作完成声明或声学10ms验收。


### 最新用户决定：200 MiB / 512 MiB

音频编码文件上限调整到 200 MiB，完整解码 PCM 上限固定 512 MiB；取代此前 100 MiB / 192 MiB 及未采用的动态预算草稿。主控服务最多登记两份音频与32 MiB附属资源，共432 MiB；接收缓存另计。两项限制必须分别通过，不代表整个应用仅占512 MiB。播放页连接LAN房间期间直接显示房间管理入口。


### 200 MiB / 512 MiB 实机压力路径

2026-10-30 使用主控独有137,528,652字节（约131MiB）合成双声道FLAC，时长600秒。经FileProvider content URI打开，并设置自定义歌名/歌手。双方均报告Web Audio解码600秒、48000Hz、双声道，预计230,400,000字节PCM（约220MiB），证实超过旧100MiB文件及192MiB PCM的路径可解码；双方显示用户自定义标题与歌手。此测试中成员出现反复重连，不能以成功解码宣称稳定播放验收通过。正在修正存活判定：控制连接收到有效消息即刷新存活时间，不等待JS对时计算完成；超过15秒无任何控制消息才判定丢失。需以修订包重测。


### 大文件重连诊断补充

修订测试中发现副设备锁屏后台的 `ForegroundServiceStartNotAllowedException`，因此此前重连不能单凭对时日志归因于文件大小。`startSyncService` 返回false以前被LAN适配器忽略，已改为立即报SERVICE_STOPPED并回收会话，避免显示连接正常却没有前台服务保障。需解锁并前台启动后重新验收稳定播放。当前已确认内容URI读取、大于旧限制的实际解码及用户自定义歌名/歌手正确，但持续稳定性仍未通过。


### 主控直读修订

按用户建议，主控直接借用服务端拥有的不可变快照与已解析元数据，移除自我HTTP下载、重复接收文件和重复hash计算。成员路径不变；暂停/恢复、全员就绪与绝对时间调度不变。原文件仍先制成快照，避免播放途中改写造成主副设备内容不同。`LanHostedMediaTest`验证复用同一个File、无新增缓存文件及错误/缺失快照拒绝。列表点歌则在云端本地禁令之前路由到LAN，不预先修改播放索引。
