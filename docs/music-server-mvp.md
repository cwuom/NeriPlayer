# Navidrome 媒体库与基础播放：首个 PR 范围

更新：2026-10-10。已合并的对比基线：`285beb6b`；当前分支：`feat/navidrome-mvp`，保留合并待提交状态。本轮查询上游已前进至 `400e278f`，尚未对齐及验证。

在音理中连接用户自己的 Navidrome / OpenSubsonic 服务器，通过现有播放器浏览、搜索和播放音乐。当前功能以服务器接入为范围，探索聚合与后续增强见[开发计划](music-server-development-plan.md)。构建、自动化与真机证据统一见[验收总报告](music-server-acceptance.md)。

## 当前实现

| 能力 | 当前行为 | 边界 |
| --- | --- | --- |
| 账号管理 | 多配置添加、连接检查、加密保存、编辑名称/地址、改密、移除 | 编辑保留配置 ID，用户名不直接改；停用、排序和图标待后续 |
| 入口 | 资源库末尾的“音乐服务器”、音乐源设置；探索保留独立入口 | 探索入口打开服务器页面，未接入探索搜索/发现 |
| 媒体库 | 专辑/单曲两类，专辑详情、封面、歌手、曲目数 | 不设独立歌手分类；专辑详情一次取得完整曲目 |
| 搜索 | 专辑、单曲分别查询服务器；专辑内即时筛选 | 每页 30 条，按上游顺序；全选/播放只作用于已加载或筛选出的歌曲 |
| 歌曲操作 | 播放全部、收藏、下一首、队尾、添加本地歌单、长按多选 | 沿用原队列、本地收藏、确认、去重与撤销；不回写服务器 star/歌单 |
| 展示 | 自定义歌名/歌手/封面、当前播放标记、圆角搜索框 | 展示覆盖保持完整服务器歌曲身份 |
| 设置搜索 | 可清空搜索、结果标题、父级路径提示 | 共享设置搜索组件的调整，也作用于原有设置项 |
| 播放 | raw 原音、服务器声明的格式/码率元数据、Media3 队列和系统控制 | 声明字段不是客户端解码实测；格式和拖动能力取决于容器、服务器与设备；无自动换源 |
| 封面 | 请求时认证，复用 Coil 与系统媒体封面 | 固定 600 像素；失败占位，不阻塞音频 |
| 歌词 | songLyrics 扩展发现、逐行/普通歌词、offset、成功结果缓存 | 无多语言选择/逐字增强；手动歌词和原有来源偏好继续生效 |
| 浏览缓存 | 专辑目录、单曲目录、专辑曲目持久化；搜索结果内存复用 | 缓存先展示，过期后刷新；失败保留快照，不能视为音频下载 |
| 下一首预取 | 顺序播放时，在非计费网络预取下一首开头，写入原播放缓存 | 最大 1.5 MiB，按缓存预算和文件长度缩小；当前播放优先，受取消和时间预算约束 |
| 失败处理 | 脱敏错误、有限传输重试、保留曲目/进度以便手动重试 | 未实现网络恢复自动续播；HTTP 416 交由 Media3 判断末尾/越界 |
| 来源边界 | 无凭据引用隔离账号与原始 ID；下载/一起听显示不可用并在执行层拒绝 | 配置迁移和共享边界专项回归安排在后续多服务器阶段 |

## 使用流程

1. 在“设置 → 第三方平台登录 → 音乐服务器”添加配置；“资源库 → 音乐服务器”的空状态也会提示这个路径。
2. 输入名称、完整基础地址、用户名和密码，连接检查成功后保存。
3. 基础地址可以带端口和反代子路径，如 `https://music.example.com:4533/navidrome/`；填写服务器基础地址，不填 `/app/` 或 `/rest/` 路由。
4. 返回“资源库 → 音乐服务器”，选择服务器。默认浏览专辑；用专辑名或歌手名搜索专辑，切到单曲后用相同关键词查歌曲。清空搜索保持当前分类；实际匹配范围以服务器索引为准。
5. 打开专辑后搜索仅筛选当前专辑，清空不离开详情；返回恢复父列表的搜索和滚动位置。
6. 点击歌曲播放，或使用播放全部、多选、收藏、下一首、加入队尾及添加本地歌单。
7. 更改地址或密码时编辑原配置并重新连接，保留原配置 ID；更换账号/实例应新建配置。移除后重加生成新 ID，旧条目不自动重绑定。

服务器配置和密码只保存在本机受保护存储中。移除配置不删除远程歌曲，也不等于清除已有媒体缓存。另一设备缺少相同配置 ID 时不能凭无凭据歌曲引用直接播放。

## 构建与验证入口

项目要求 JDK 17、Android Platform 37.0、NDK 27.0.12077973、CMake 3.22.1，并初始化歌词子模块。遵循[贡献指南](../CONTRIBUTING.md)。

```sh
./gradlew :app:assembleDebug
./gradlew verifyModularization
```

Debug 包名 `moe.ouom.neriplayer.debug`，支持 Android 9（API 28）以上。Debug 与正式包分别保存数据。已安装版本、哈希与本轮质量检查结果见[验收总报告](music-server-acceptance.md)，构建成功与真机操作验收分别记录。
