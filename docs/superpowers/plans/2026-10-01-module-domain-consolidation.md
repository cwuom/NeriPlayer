# 模块业务域收敛实施计划

## 全局约束

- 31 个自有库收敛为设计矩阵中的 22 个，api 保留，移除 core/data/feature 分类，不保留别名或空壳构建节点
- 保留已有未提交改动、生产类全名、数据库 schema、序列化格式、资源、测试及现有质量门禁；不升级依赖、不提交、不推送
- 词幕输出由 lyrics:runtime 内部 integration 职责维护，播放器只提供快照和生命周期输入；协调器和进度计算继续 internal
- 使用 gradle/owned-modules.txt 作为自有库登记的唯一来源，构建和质量聚合支持一级和嵌套领域目录
- playback:logic 的九个 policy 叶子包与 runtime/audio/queue 包保持单向隔离，USB policy 仍归 playback:runtime
- 保持 lyrics:parser 与 lyrics:runtime 的独立边界，禁止引入循环依赖
- 仅操作现有工作区，不创建 Worktree；仅在模拟器上执行设备验证

## 任务

### 1. 记录基线与登记迁移

保存当前文件哈希和改动基线。创建单一模块登记，调整 settings、app 覆盖率、根验证任务。目录移动统一串行完成，合并时检查文件冲突。

### 2. 领域构建合并

将 common/logging、四个播放基础库、两个元数据 API、同步三库、一起听三库分别合并。保留插件、api 可见性、测试依赖、consumer rules、资源和 schema。其它库按矩阵改归属，项目依赖去重，合并后的自身依赖删除。

### 3. 词幕职责迁移

迁移 Manager、位置推送、代次协调及现有测试，抽取 PlayerManager 中词幕异步编排和偏移跟踪。使用窄输出控制入口保留内部可见性。添加针对取消、快速切歌、偏移快照和生命周期的回归验证。迁移 SDK、Manifest metadata、标签资源与 R8 规则。

共享来源偏移算法直接复用：现有 LyricDefaultOffset.kt 及对应测试字节不变移入 lyrics:parser，保持原包名和函数接口，settings 持久化仍归 local。通过精确文件所有者登记维护该例外，避免复制算法或歌词反向依赖 local。

### 4. 结构和依赖门禁

修改边界脚本与回归测试，从登记读取真实模块。使用明确领域依赖规则代替类别层级。补齐精确 policy 域规则，保留主源码预算、包路径、无环、无应用容器依赖和未登记节点检查。

### 5. 质量范围及文档

更新 CRAP 路径、编译后的 internal 方法后缀、同步和一起听的独立质量聚合；新词幕控制器全目录入范围。更新源文件定位测试、CI、IDE 和双语 README/CONTRIBUTING，各模块 README 说明职责和构建入口。

### 6. 集成验证和审查

运行 Python 质量工具测试、模块边界检查、受影响库 JVM 测试、CRAP/领域检查、lint、构建逻辑测试和 Debug/设备测试 APK 构建。执行 verifyModularization，检查最终合并 Manifest 与资源。可用模拟器上执行相关设备测试；实际词幕系统服务展示单独列为未验证。

独立审查此次增量改动，修复确认的问题。核对迁移前后所有源码、测试和非构建资产；审查完整 diff，清理本次临时资源。

## 审查重点

检查是否误丢原有未提交文件、改变类名或数据库格式、漏迁资源或测试、扩大公共接口、漏登库、形成隐含循环、缩减质量范围，以及词幕请求代次和偏移是否仍对应同一歌曲。

## 执行记录

基线位于本次任务的临时目录，仅保存工程文件；实施结果和验证以实际命令输出为准。并行任务只写互不重叠的文件，公共登记与目录移动由主代理串行完成。
