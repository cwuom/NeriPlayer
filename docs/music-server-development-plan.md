## 今晚的三个交付物

1. [API 规范 v0.1](music-server-api.md)：覆盖规划内接口、能力缺口、认证与资源身份。
2. [Android MVP](music-server-mvp.md)：现有音理应用内的多服务器基础接入，交付源码和构建产物；如有未通过验收项明确列出。
3. 本计划：从原型到首版、再到增强功能的依赖、交付范围和验收门槛。

“完整 API 规范”意味着讨论所需的边界完整；今晚原型只实现 P0。后续不以一次全量 PR 承载所有能力。

## 提交顺序

```text
已有 issue #490：贴 API 与 MVP 范围摘要，维护者确认接入方向
        ↓

        ↓

        ↓

        ↓
```

本地实现可以先推进，合并前与维护者对齐。是否把设计文档留在仓库取决于评审，不要求先合并纯文档 PR。所有线上发布由用户自己的账号完成。

## 弱网与播放中断恢复

首个本地 commit 保存可继续开发的原型基线，不承诺完成全部容错能力。以下是后续计划，尚未作为服务器来源完成验收；优先复用现有播放状态、缓存、请求取消和恢复机制。

| 场景 | 预期行为 | 交付安排 |
| --- | --- | --- |
| 建连或首字节慢 | 显示连接与缓冲状态；可取消、切歌；超时后可重试 | 首次提交沿用现有能力，后续补服务器错误分类与总等待预算 |
| 持续下载速度低于音频码率 | 当前曲目优先，暂停投机预取；允许积累更多缓冲 | 弱网优化阶段；服务端支持时再提供用户可控的低码率转码 |
| 播放中短暂断连 | 消耗已有缓冲，保留曲目与进度；有限重试后从原位置恢复 | 基础接入收敛后的恢复专项 |
| 完全离线或服务器持续不可达 | 可用缓存继续播放；缓存不足则保留现场等待，提供重试或跳过 | 恢复专项；避免把同服务器全部歌曲逐首试错 |
| 401/403、资源删除、限流 | 分别提示重新认证、资源不可用、稍后重试 | 错误分类先做；恢复与退避随后接入 |
| 网络恢复或切换 Wi-Fi/移动网络 | 在同一播放会话且用户仍要求播放时尝试恢复；尊重计费网络设置 | 后续网络感知恢复 |

### 实现边界

1. 播放中卡顿应同时观察缓冲量和播放进度，区分缺数据与解码/音频输出异常。下载速度长期低于音频码率时，有限缓存只能延后再次卡顿，不能保证持续播放。
2. 现有启动和运行中 watchdog 可作为恢复入口；JSON 请求取消已由网络层传递到 OkHttp。不要在仓库、拦截器、播放器各自增加一套无限重试。
3. 现有分块 Range 策略只针对部分 YouTube 与网易云资源，不能因为服务器走同一数据源就宣称已经支持服务器断点续传。需验证原音流的 Range、长度及定位行为；不支持时按 Media3 可定位能力恢复，并明确限制。
4. 复用原队列与播放位置，恢复请求绑定当前歌曲和播放会话。用户暂停、切歌、停止或退出相关会话后，旧任务不能再自动响起；短期自动恢复设总时限，超时交给用户重试。
5. HTTP 与协议错误保留脱敏分类。认证错误停止自动尝试；瞬时错误采用有上限的退避；限流遵守可用的 Retry-After。断网和服务器不可达不应默认连续跳完整张专辑。
6. 已有 onPlayerError 含失败后推进队列的分支和连续失败上限。需要针对服务器级故障复审；当前原型尚未实现“服务器不可达时保留当前曲目等待”的完整策略。
7. 下一首预取复用同一媒体缓存，受当前缓冲、取消、空间和网络策略约束；暂不为此建立独立下载系统。转码如后续开放，须将格式与码率纳入缓存表示身份。
8. 首阶段在原服务器内恢复；跨服务器或网易云替代音源需要明确匹配与用户选择，不能仅凭同名歌曲静默替换。

以上是增量实现顺序，不要求全部挤进首个 commit 或同一个 PR。后续验证应分别覆盖高延迟、低吞吐、短断网、长期离线、认证失效和切歌取消；具体阈值通过测量确定。

## 模块改动原则

| 需求 | 改动位置 | 控制范围 |
| --- | --- | --- |
| 新协议 | :platform/subsonic | 新增客户端与仓库，依赖现有网络层 |
| 来源编码 | :model + 现有 identity helper | 沿用 SongItem 字段，保留完整来源引用 |
| 页面入口 | Library、Explore、PlaybackSource settings | 使用现有导航和页面组件，收敛原型临时入口 |
| 播放 | playback host + URL 分支 | 返回现有 SongUrlResult，不重写 PlayerManager |
| 图片 | 共享 HTTP 资源解析 | 认证只绑定对应资源；保持 Coil 和系统封面复用 |
| 歌词 | PlayerLyricsProvider + 仓库映射 | 复用现有 LyricEntry、来源偏好和匹配界面 |
| 后续聚合 | 现有搜索状态/匹配工具的小适配 | 不先迁移所有平台到新 Provider 大框架 |

只有已经确认现有模型无法表达某项功能时，才提出新的字段或小接口，并在 PR 解释必要性。
