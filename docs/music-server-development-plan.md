## 实现与验证约束

优先复用现有 `SongItem`、`SongUrlResult`、`LyricEntry`、host 注入、网络取消、队列状态和缓存设施。只在实际调用方需要时增加小接口，不迁移所有平台到新 Provider 框架。库模块不得读取 app 或全局容器；模块边界遵循[贡献指南](../CONTRIBUTING.md)。

弱网专项应分别测高延迟、低吞吐、短断网、长期离线、认证失效和切歌取消。低吞吐时当前播放优先，暂停投机预取；Range、容器与转码定位能力以实际服务器为准。复用现有错误处理入口，不在仓库、拦截器和播放器分别建立无限重试。

账号移除、改密、切服或退出时旧请求不能覆盖新状态。身份与缓存保留配置 ID、原始 ID 和实际表示；任何代理 Long ID 都不能代替服务器 API 的原始字符串 ID。认证材料不进入普通导出、同步、日志或 PR 附件。

- [ ] 以音理原有页面和歌曲操作为参照，整体复核服务器接入的入口、顺序、状态保留和反馈；尽量复用现有组件与行为约定，服务器能力不同的地方给出清楚提示。

- 搜索、清空、切换专辑/单曲、进入详情与返回时，搜索范围和列表位置符合预期；保留已确定的两类搜索方案。
- 播放全部、下一首、队尾、收藏和添加本地歌单时，顺序、重复处理、提示与撤销沿用原有约定。
- 长按、多选、全选、清空和批量操作与原歌曲列表一致。
- 加载、刷新、脱机、空结果、失败和不可用操作的反馈与原页面一致。

范围限于服务器接入。发现差异后记录为具体小任务，再逐项处理；此项保留在全部待办末尾，作为各阶段功能完成后的整体检查。
